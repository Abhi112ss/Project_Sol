### Infrastructure Mechanisms (`backend/src/infrastructure/`)
- **Response Envelope (`envelope.interceptor.ts` -> `ApiEnvelopeInterceptor`):**
  - Wraps normal responses as `{ success: true, data: payload ?? null, meta: { requestId, serverTime }, error: null }`.
  - **Crucial detail:** When service returns `{ items, pagination }` (`isPaginatedPayload`), `ApiEnvelopeInterceptor` hoists `items` directly to `data: payload.items` (array!) and places `pagination` inside `meta.pagination` (`{ page, limit, total, totalPages }`). Always use `apiRequestWithMeta()` on paginated endpoints (`GET /admin/employees`, `GET /admin/audit-logs`).
- **Exception Filter (`http-exception.filter.ts` -> `GlobalExceptionFilter`):** Returns `{ success: false, data: null, meta: { requestId, serverTime }, error: { code, message, details? } }`.
- **Idempotency (`idempotency.interceptor.ts` -> `IdempotencyInterceptor`, `@Idempotent()`):** Checks optional `X-Idempotency-Key` header against `idempotency_keys` table using SHA-256 `(method:path:body)` hash; replays stored response on exact retry, throws `ConflictException('IDEMPOTENCY_KEY_PAYLOAD_MISMATCH')` if payload differs.
- **Event Outbox & Socket.IO (`outbox.service.ts`, `transport.gateway.ts`):**
  - Transactional `outbox.enqueueInTx(tx, ...)` writes domain events inside Postgres transactions alongside business writes (Kafka deferred per `ADR-002`).
  - `TransportGateway` mounts WebSocket namespace `/ws/transport` with room helpers `WS_ROOMS.orgOps(orgId)` and `WS_ROOMS.driver(driverId)`.
- **BullMQ Queues (`queue/queue.constants.ts` & `queue.module.ts`):** 7 queues configured over Redis.
- **Shared Domain Logic Already Implemented (`infrastructure/shared/` & `modules/routing/`):**
  - [`state-machines.ts`](file:///d:/prac/project_sol/backend/src/infrastructure/shared/state-machines.ts): `TRIP_TRANSITIONS`, `PASSENGER_TRANSITIONS`, `assertTripTransition(from, to)`, `assertPassengerTransition(from, to)`, `isPassengerPendingForRouting(status)` (tested in `state-machines.spec.ts`).
  - [`delay.util.ts`](file:///d:/prac/project_sol/backend/src/infrastructure/shared/delay.util.ts): `calculateDelaySeconds(scheduledAt, actualAt)` separating arrival delay from wait duration (tested in `delay.util.spec.ts`).
  - [`maps.util.ts`](file:///d:/prac/project_sol/backend/src/infrastructure/shared/maps.util.ts): `buildGoogleMapsNavigationUrl(lat, lng)` and pure spherical `haversineDistanceMeters(lat1, lng1, lat2, lng2)` fallback (tested in `maps.util.spec.ts`).
  - [`routing.module.ts`](file:///d:/prac/project_sol/backend/src/modules/routing/routing.module.ts): `RoutingService.selectNextStop(stops)` — picks lowest `sequenceNo` where `isPending === true` and attaches Google Maps navigation URL (tested in `routing.service.spec.ts`).

### Phase 2 Admin Backend Logic Implemented (`backend/src/modules/`)
1. **Bookings & Duty Approvals (`bookings.module.ts`, `approvals.module.ts`):**
   - `BookingsService.createBooking`: Verifies employee, shift, office, and pickupLocation belong to active org; blocks duplicate active bookings `(orgId, employeeId, travelDate, shiftId, direction, status != 'CANCELLED')`; creates `PENDING_APPROVAL` booking; writes `audit_logs`.
   - `BookingsService.cancelBooking`: Allows cancellation in `PENDING_APPROVAL` or `APPROVED` state with reason.
   - `ApprovalsService.getQueue`: Filters by `status` (default `PENDING_APPROVAL`), `travelDate`, `direction`, `shiftId`, `officeId`, `department` (`ilike`), `corridorTag` (`ilike`), ordered by `scheduledPickupAt`.
   - `ApprovalsService.bulkDecide`: Validates all `bookingIds` exist in org and are `PENDING_APPROVAL`; batch-updates `bookings.status` to `APPROVED` or `REJECTED`; inserts `approvals` rows; writes `audit_logs` + `outbox_events` (`NOTIFICATION_EVENTS`) per booking.
2. **Manual Dispatch & Modification (`dispatch.module.ts`):**
   - `DispatchService.publishManualDispatch`:
     - Validates unique `sequenceNo` across `stops`.
     - Inside transaction: verifies `driver` (`!isSuspended`), `vehicle` (`isActive`), `office`, and `shift` belong to `identity.organizationId`; enforces `stops.length <= vehicle.seatingCapacity` (`422 VEHICLE_CAPACITY_EXCEEDED`).
     - Verifies all `stops[i].bookingId` belong to `org`, have `status === 'APPROVED'`, and match `(travelDate, shiftId, officeId, direction)`!
     - Generates unique `tripCode` (`TRP-YYYYMMDD-<6hex>`), inserts `trips` row (`status: 'ASSIGNED'`), inserts ordered pickup `trip_stops`, automatically appends a final `OFFICE` terminus stop when `direction === 'LOGIN'`, inserts `passenger_assignments` (`status: 'SCHEDULED'`), updates `bookings.status` -> `'DISPATCHED'`, writes `trip_events` (`TRIP_DISPATCHED`), `audit_logs` (`TRIP_MANUAL_DISPATCHED`), and `outbox_events` (`ASSIGNMENT_EVENTS`).
     - Post-commit emits Socket.IO `'trip.status.changed'` to `orgOps` and `driver` rooms.
   - `DispatchService.modifyDispatch`: Blocks terminal trips (`COMPLETED`/`CANCELLED`/`ABORTED`), re-checks replacement vehicle capacity if `vehicleId` supplied, safely swaps `trip_stops.sequenceNo` in two passes (`+1000` temporary offset to avoid unique constraint `(trip_id, sequence_no)` collisions before writing final `1..N`), records `TRIP_DISPATCH_MODIFIED` in `trip_events` and `audit_logs` with `beforeJson`/`afterJson` diff.
3. **Overview & Trips (`trips.module.ts`):**
   - `getOverview`: Runs 15 parallel queries for `kpis` (`totalEmployees`, `activeDrivers`, `availableVehicles`, `assignedVehicles`, `activeTrips`, `completedTrips`, `cancelledTrips`, `noShowPassengers`, `delayedPickups` (`arrival_delay_seconds > 120`), `pendingApprovals`, `approvedAwaitingDispatch`, `activeEmergencies`), `upcomingShifts`, `recentTrips` (`slice(0, 10)`), and `openAlerts`.
   - `getTripDetail`: Returns `{ trip, stops, assignments, events, noShows }`.
4. **Employees CSV Import & Profile (`employees.module.ts`):**
   - `parseCsvLines`: Handles quoted fields & escaped quotes (`""`), CRLF/LF line endings (unit tested in `employees.csv.spec.ts`).
   - `importCsv`: Validates rows with `csvRowSchema`, resolves `officeCode`/`shiftCode` to active org records, idempotently skips duplicates, creates `users` + `employees` + `memberships` (`EMPLOYEE`) + optional `employee_locations`, writes audit log.
   - Also provides `getDetail`, `updateEmployee`, `listHistoricalTrips`, `listSavedLocations`, `addSavedLocation`.
5. **Fleet & Governance CRUD (`drivers.module.ts`, `vehicles.module.ts`, `vendors.module.ts`, `offices.module.ts`, `shifts.module.ts`, `organizations.module.ts`, `audit-logs.module.ts`):** Full `GET`/`POST`/`PATCH` routes plus `POST /admin/drivers/:id/suspend`, `GET /admin/drivers/:id/schedule`, `POST /admin/vehicles/:id/assign-driver`, `PATCH /admin/organizations/:orgId/settings`.
